## Owner's fixes after testing Telegram codes (2026-10-08; branches `fix/phone-sign-in-messages` (both repos) → `fix/phone-code-limits` (backend) → `feature/phone-only-sign-up` (both repos))
- [x] Phone sign-in (`/login/phone`): a number with no account used to get the same "Check Telegram" page as a real one (by design, to hide who is a customer), so people waited for a code that never came. Sign-up already says when a number is taken, so hiding it protected nothing. Now step 1 says "We couldn't find a Bookly account with this verified number…" on the number and stays put; a number Telegram can't reach and a failure on our side (balance, gateway) each get their own message; deactivated accounts are told so. The code page reads "We sent a 6-digit code to the Telegram account of …"; the page links to sign-up too.
- [x] No cap on Telegram codes per number (owner: a missing code is often our side). It stays available as `PHONE_CODES_PER_HOUR` / `PHONE_CODES_PER_DAY` on the API (off by default), and codes Telegram couldn't send never count. Still in place: Turnstile, the per-visitor limit (3 sends per 10 minutes), 5 wrong guesses throw a code away. New roadmap item: low-balance alert for the Telegram Gateway.
- [x] Sign-up with Telegram doesn't need an email (owner): the field shows "(optional)", "For receipts and order updates. You can add it later."; email sign-ups still require it. The API takes over an unfinished phone-only sign-up with the same number instead of leaving duplicates; unfinished ones are removed after 48 hours like the rest. A phone-only account signs in with its number + Telegram code and can add an email later in Sign-in & security. The password stays required (it confirms sensitive changes, and works for signing in once an email is added).
- [x] Roadmap (owner's notes): order updates and receipts for customers in Telegram (Phase 4, needs our own bot), new-order notices to the owner and a staff Telegram group (Phase 3), Telegram balance alert (Phase 2).
- [x] Verified: lint (0 errors, same 5 warnings), typecheck, 259 unit tests (new: no-account message and sign-up link, phone-only sign-up, email still needed for email codes, schema), build; backend 294 tests + Pint. Browser pass against the local API with a stand-in Telegram Gateway: unknown number told so with no code sent; phone-only sign-up with the email empty (code to Telegram, no "send by email instead"); five codes in a row for one number with no cap; the account saved with no email and a verified phone; signed out and back in with the number + code; 375 px dark; no page errors.
